# Changelog

Entries record changes at the time they landed and can be superseded by later entries; they are not current configuration or qualification claims. Use [the documentation index](docs/README.md) for active contracts. “Unreleased” means not promoted here, not installed or physically passed.

## Unreleased

- Documentation audit: route current launcher work through one index; reconcile M2, Maps-first readiness, masked Radio recovery, component catalogue, binary Day/Night, release identity and retired theme/Leaflet/n3host guidance. Mark old investigations and test instructions as historical without rewriting their evidence. No runtime change or new device qualification.

- Integration hardening: give each N3 phase its own deadline, retain the exact target in diagnostic snapshots, ignore invalid replacement starts while a display is owned, invalidate late optional-host bindings on release, and require a non-null display frame after target-launch acceptance before reporting rendering. M1 and N0–N2 remain the defaults; TS18 physical checks are deferred.

- Docs: `docs/REFERENCE_ADOPTION.md` (pinned reference study with adopt/reject decisions) and `docs/WP_LEDGER.md` (work-package status, physical matrices and rollback).

- Campaign kit: capture the launcher's `TS18Startup` phases (live and history) and the framework's `Displayed`/`Fully drawn` lines for the launcher and Organic Maps only; `compare` now reports instrumented phases per launcher process (boot_id, phase offsets, spans, missing expected phases, framework launch timing) without inventing statistics.

- Topway: the one-off source observation now also requires a separate default-OFF acknowledgement that names the unresolved shared-callback risk; the descriptor-only check is unaffected.

- Setup: a short, skippable, repeatable checklist (`SetupActivity`) covering Home (through the system role/Home screen), Music, Radio and Navigation apps (existing picker), notification access (Android Settings), the optional root listener grant (status plus a link to its informed switch), experimental N3/M2 status and rollback. Offered once after Home has drawn, only on new installs with no apps chosen, and available any time from Settings. It never grants or takes anything itself.

- M2: source-specific passive readiness. One epoch per accepted boot/wake/HOME/storage trigger binds a Direct source's own browser service when not running and sends `prepare()` once only if the source advertises `ACTION_PREPARE` and has no loaded item; ready means the session reports a loaded item. Never Play, Activity, focus or root; user taps supersede it; bounded 8 s + 5 s. HOME shows "Getting ready…". The API 29 emulator IPC run now also proves PREPARE loads without playing, source-death reporting and retry after death. Auxio-TS's existing `onPrepare()` contract is used unchanged.

- N3 navigation backend (experimental, default OFF): `NavigationFeatureFacade` (legacy vs N3 ownership; legacy automatic launch refused while N3 holds a display), `N3NavigationBackend` with immutable `N3Snapshot`s, `N3PresenterView` SurfaceView presenter, a launcher-owned private VirtualDisplay with first-frame pixel observation before presentation, one user-initiated `setLaunchDisplayId` launch, real MotionEvent conversion (pointer IDs, action index, times, history), display-scoped Back through the display-owner input forwarder (fail-closed), surface detach/reattach without relaunch, Retry N3 / Open navigation normally / Use legacy navigation. New separate optional `n3host` APK module (inert unless built with an explicit identity): Binder service + framework-free `DisplayHostCore` enforcing the hardened `N3HostPolicy` (atomic reservation, leases, host-recorded geometry, action validation, death cleanup). See `docs/NAVIGATION.md`.

- Qualify the M2 cold-start path over real cross-process IPC on the API 29 emulator: the androidTest APK now carries an exported `MediaBrowserService` fixture in its own package and process, and a new `-e m2_browser 1` instrumentation mode drives the production `BrowserSessionStarter.FrameworkConnector` through discovery, cold bind, package-owned token, one Play confirmed by the same session, teardown and a fresh reconnect. The CI emulator smoke requires its PASS line. This is emulator IPC evidence only, not TS18 or Auxio-TS physical qualification.

- Add read-only Topway capability reporting (`oem/`): `DeviceCapabilities` identifies `com.tw.service.xt` (version, signer, APK SHA-256 against the verified binary, exported endpoint) and reports caller identity, NavRadio+/stock-radio session strategies, a permanently BLOCKED native-radio boundary and UNKNOWN illumination. Two manual Settings actions check the service interface and, on the verified binary only, observe the active Topway source once through a temporary status callback that is always removed. Nothing is written to Topway, tuner, light, volume or MCU state; the music callback is never registered. See `docs/OEM_CAPABILITIES.md`. TS18 behaviour is NOT_RUN.

- Add a process-local startup phase timeline (`StartupTimeline`, log tag `TS18Startup`): process start with boot_id, Application create, startup kind, HOME create/content/first draw (`reportFullyDrawn`)/focus, first M1 music/radio queue readiness and navigation readiness, plus timed spans for each synchronous `Application.onCreate` step. Measurement only; behaviour unchanged. See `docs/STARTUP_TIMELINE.md`.

- N3: add `N3InputMapper` (aspect-fit, inset-aware, multi-pointer mapping from presenter view to display pixels, whole-gesture ownership, cancel on malformed input) and `N3HostPolicy`, the admission contract for a future disabled-by-default privileged display host (exact caller package/certificate/user, exact allowlisted component, owned display, bounded geometry/pointers/coordinates/rate, release on caller death). Neither is reachable at runtime; no host, permission or manifest entry is added. See `docs/NAVIGATION.md`.

- When neither Music nor Radio uses the Legacy engine, stop the legacy session monitor entirely (subscription, callbacks and its one-second visible tick) instead of computing state that is then discarded.

- Add the experimental, independent N3 package (`navigation/n3`): a generation-tagged session state machine, a feasibility classifier and a read-only probe (Settings → Experimental · N3 display host) that asks Android whether the selected navigation Activity may start on a private launcher-owned display. N3 is not a selectable surface; N0–N2 are unchanged. See `docs/NAVIGATION.md`.

- Retire the DoFun/RePlugin theme product: remove `theme/`, the RePlugin fetch, theme installers/rollback scripts and `docs/INSTALL_TS18.md`, and the theme lint/build/envelope steps in CI. The production release pipeline now builds, qualifies and publishes only `com.cbkii.ts18launcher` (`TS18-Launcher-<tag>.apk` with an install-tools ZIP). Qualification requires v2 signing and v1 only below minSdk 24. The installed OEM DoFun host is untouched.

- M2 Direct can now start a source that is not running, on a Play tap only, through that app's own exported `MediaBrowserService`: the offered token is verified against the requested package, pinned, sent one `play()` and confirmed by that session. No Activity launch, root, startup preparation or retry. Sources without such a service stay "Not running"; HOME distinguishes startable, starting and unavailable.

- Add the opt-in **M2 Direct** media engine (`media/direct`): exact configured package, one pinned session token, one directional dispatch per tap confirmed only by that session, truthful `ACKNOWLEDGED` / `SENT_UNCONFIRMED` / `UNSUPPORTED` / `SOURCE_LOST` / `FAILED` results, and no launching, binding or preparation of any app. Selectable per source under Settings → Media → Control engine; Legacy remains the default. HOME shows a non-live Direct source as unavailable with a one-line reason instead of a ready Play button. See `docs/MEDIA.md`.

- Add per-source media engine selection behind one `MediaFeatureFacade`: `music.engine` and `radio.engine` (`legacy` | `m2`, default and fallback `legacy`) are persisted, exported/imported and reset independently. The existing machinery is kept unchanged as the M1 legacy engine behind `LegacyMediaBackend`; a deselected engine is detached before the selected one may act, cannot command, and cannot publish state. Legacy startup preparation skips any source not served by the legacy engine. This build contains no second engine, so a stored `m2` resolves to legacy.
- Root is no longer used implicitly to enable the launcher's notification listener. The Android "Notification access" screen is the default; an explicit, device-local switch (off by default, never exported, cleared by import/reset) permits one root grant of the launcher's own listener. If access is removed after such a grant, the consent withdraws itself and access is not restored.
