# Repository working rules

- Target CB's exact Topway TS18 first: Android 10/API 29, physical 1280 x 720. Present exact-device evidence outranks historical assumptions.
- **Local/offline/private by default** is repository policy. Core HOME operation must not require Internet access. **No analytics** are added by default: do not add remote analytics, tracking, cloud telemetry, remote configuration or automatic upload of diagnostic/user-behaviour data. Diagnostics stay bounded, local/exportable and user-controlled.
- The standalone launcher is a separate ordinary Android package (`com.cbkii.ts18launcher`). The legacy DoFun/RePlugin theme remains a rollback/reference lane until standalone HOME passes physical qualification.
- Do not reuse `launcher.variety.theme.plugin.sfp_cbk_black` as the standalone launcher identity. That package remains the legacy DoFun/RePlugin plug-in identity.
- Preserve the exact-device SystemUI safe area: keep visible/interactive launcher content at or left of x=1225 and below the observed top SystemUI boundary when the Activity receives full physical bounds. The dashboard retains a 96 px rail and 88 px top media strip; the rail may mirror left/right without entering the Topway SystemUI region. When Android decor already consumes bars, use fitted content bounds rather than adding insets twice.
- Responsive behaviour is exact-device/known-landscape only: physical 1280x720, decor-fitted bounds, and the Topway right-sidebar shown/hidden profile when evidence supports it. Do not turn HOME into a generic split-screen/phone/tablet responsive launcher.
- Preserve the continuous top-strip structure `[Radio controls] [shared active metadata] [Music controls] [DD MMM]` (Radio/Music groups may swap sides by user preference). DD MMM is display-only, transparent and compact; it is not a Settings shortcut.
- Source hierarchy is asymmetric but both sources stay actionable: selected Radio/Music gets the stronger semantic accent treatment; the inactive source retains a subtle accent cue/gradient and must never look disabled. Use restrained tonal gradients rather than extra chrome/shadows.
- Keep HOME driver-facing controls icon-first and glanceable: use the pinned local Material Symbols Rounded family for fixed/override glyphs, stable transport positions, large touch regions, visible focus/pressed/selected feedback and restrained black/charcoal surfaces. Orange is the default semantic accent, but the bounded Material-derived accent-hue preference may recolour accent-role elements only. Keep physical TS18 safe coordinates in raw pixels but inner icon/text/padding dimensions in semantic resources.
- HOME rail order is fixed as Apps at top, optional 3-6 configurable quick slots in the middle, Navigation fixed at bottom. Quick 1 defaults to Settings. When HOME shortcuts are enabled, visible slots should divide the available middle rail space according to active count rather than being permanently packed for six. The whole HOME-shortcuts section can be disabled; when disabled, hide its count/editor settings too. Navigation remains at the bottom.
- Each HOME/drawer quick slot has separate App and Icon semantics. App controls actual package/role authority. Icon is `Auto` or a visual-only curated Material Symbols Rounded override and must never change what launches. Auto shows the real installed-app icon for explicit app shortcuts and the semantic role icon for role shortcuts. Settings previews must follow the same truthful identity rule.
- Accent selection is deliberately bounded and simple: use the Material-derived palette only and present it as a compact strip of colour circles. Do not add an arbitrary HSV picker unless later evidence establishes a real need.
- Do not add a first-run wizard unless physical/user testing identifies an actual discoverability failure. Sensible defaults plus the default Settings shortcut are the onboarding model.
- The in-HOME app drawer may use installed application icons for application identity. Keep the five-column grid, five configurable quick-access slots and local app search with a visible voice-search action, without introducing a background indexer or remote service unless physical evidence justifies it.
- Keep the base launcher small and event-driven. Prefer platform Android Views/Java and ordinary framework APIs. Do not add Compose, AppCompat, Material runtime, Room, DataStore, RxJava, DI frameworks, image loaders or general-purpose Android networking stacks without a measured requirement.
- The Leaflet map is an **experimental physical-test comparator**, OFF by default on clean installs while preserving an already-stored explicit map preference on upgrades. Do not spend further PR #10 scope on Leaflet presentation. A polished map-unavailable/retry placeholder may be reconsidered only if physical testing proves this experimental approach worth retaining; otherwise replacement/windowing belongs to the separate navigation architecture thread.
- When enabled the Leaflet surface remains lifecycle-bound, local/pinned and restricted to exact OSM raster tile requests through the launcher-owned TileBroker/cache. Preserve identifying User-Agent, bounded timeouts/cache, no bulk prefetch, no arbitrary browsing and no JS bridge. The raster cache cannot consume other navigation apps' offline databases.
- Do not implement the separate future Organic Maps/DoFun/freeform/PiP replacement architecture in PR #10 unless explicitly re-scoped.
- Network availability is optional: core HOME operation must start and remain usable without Internet access. TileBroker may treat only a definite no-network report as offline and must not treat network presence as proof of Internet/OSM reachability. Offline-capable navigation/media apps are recommendations, never launcher dependencies.
- Experimental map controls are optional UI only: zoom/follow controls may be hidden as a group. Do not duplicate the permanent Navigation rail endpoint inside the map. When visible, map controls stay on the opposite edge from the rail. Display and map appearance share Auto/Day/High contrast/Dim/Night; accent hue is a separate semantic accent authority. Healthy map status stays hidden; expose only meaningful locating/loading/offline/error states.
- Organic Maps remains the preferred offline navigation authority. `docs/ORGANIC_MAPS_MODES.md` records exact current fork location modes as future integration targets only. Do not call private/JNI mode APIs cross-package, reflect into Organic Maps, inject root input, invent broadcasts or assume arbitrary Activity embedding.
- The launcher may request location only while its experimental map is active/visible. Do not hold wake locks or run periodic background GPS/network polling.
- Generic music uses one selected Android MediaSession authority obtained through notification-listener access. Watch session membership/callbacks and retain the visible-only reconciliation fallback proven useful on the TS18. On this exact unit `com.tw.media` is Auxio-TS; do not treat that package as stock Topway evidence.
- Radio is a separate authority. NavRadio+ (`com.navimods.radio`) is a third-party app, not stock Topway evidence. A configured radio app may be observed/controlled through its own MediaSession when available, but never synthesize a radio MediaSession or broadcast commands blindly across several paths.
- Driver-facing Radio/Music Previous/Play-Pause/Next controls stay enabled. A button press may use a bounded public-source bootstrap: exact matching MediaSession, exported standard `MediaBrowserService`, then one ordinary app launch plus bounded retry. Do not create another player/session/audio-focus authority. Unsupported actions ultimately report a short visible failure rather than remaining disabled or dispatching guessed commands.
- Optional HOME-start media warm-up may pre-connect exported MediaBrowser services only; it must not intentionally foreground-launch source Activities. The preference must be user-disableable.
- When starting a non-playing Radio/Music source, best-effort pause the genuinely playing opposite source first. Do not make the launcher an audio-focus owner.
- Native Topway music/radio package identities and control contracts remain unverified until separately exercised on the exact unit. Prefer their real public MediaSessions if present; add a Topway-specific adapter only from exact recovered evidence.
- Keep Topway/vehicle integration behind a narrow adapter. Public Android/package paths come first. Add private Topway binder/property/broadcast/MCU behaviour only from exact recovered contracts and keep failures fail-open.
- DoFun, TWCore, stock radio/music/Bluetooth, SystemUI, vehicle services and updaters remain protected. Replacing HOME does not grant their signature/UID/SELinux authority.
- Magisk-root access may be used for bounded one-time setup/diagnostics where materially useful, but root does not grant platform signing, UID 1000, protected SELinux, MCU/CAN authority or safe partition writes.
- Never automatically clear DoFun data, set SELinux permissive, broadly chmod/chown, delete protected packages or write `/system`/`vendor`. DoFun remains enabled as recovery HOME during qualification.
- The HOME capability must be staged: ordinary launcher Activity first; enable HOME alias only after explicit user action; preserve a reversible path back to DoFun.
- `scripts/termux/collect-window-media-evidence.sh` is read-only. It may read root-private launcher preferences if authorised, but must not change settings, tasks, packages, playback or window state. Bounded/blocked captures are UNKNOWN rather than evidence of absence.
- Reverse-camera hand-off/return is roadmapped physical validation, not current launcher functionality. Do not add reverse-camera handling without exact evidence.
- Steering-wheel controls remain owned by the existing native system path. Do not add launcher interception unless exact evidence identifies a concrete unhandled event/regression.
- Vehicle telemetry is very-low-priority roadmap only; do not add persistent OBD/MCU/CAN widgets to the current launcher.
- Before changing typography/icon/touch geometry again, capture exact TS18 `wm size`, `wm density`, `densityDpi` and relevant display metrics. Do not claim the current raw-pixel interaction targets equal the intended dp targets until physically verified.
- Do not claim native radio/music, Bluetooth, projection, steering-key, reboot, cold-boot, reverse-camera or ACC behaviour passed unless physically exercised.
- Legacy DoFun theme work must preserve its independently signed clean declarative identity and must not copy/forge/transplant vendor signers or assets.
- For the legacy theme, preserve the audited compatibility envelope unless stronger evidence requires change: minSdk 16, targetSdk 26, compileSdk 29, Qihoo360 RePlugin 2.3.4, no native libraries, minimal no-component manifest and independent signing.
- Keep the legacy declarative visual contract: black/white with warm pink/red/orange/brown accents; no cool cyan/blue accents, album art, visualiser or decorative icon backgrounds.
- Keep declarative theme work separate from executable media integration. A compatibility adapter may consume several evidence-backed paths, but each action must select one playback authority and dispatch exactly once.
- Do not commit vendor APKs/assets, decrypted vendor code, signing keys, device identifiers or logs.
- Donor-slot installation must leave DoFun `p.l` unchanged by default, verify the donor path is inside DoFun `app_p_a`, back up before mutation, overwrite only validated donor bytes, verify hash and fail closed on unexpected paths/layouts.
- LSPosed feasibility collectors must remain read-only against LSPosed/DoFun configuration. Establish framework/API, ABI/zygote, DoFun scope and target-process injection evidence before hooks. Any first hook must be log-only, exact-package-scoped, bounded and fail-open.
- Termux helpers must follow the engineering script standard: bounded execution, explicit failure policy, private work state, narrow root use, verified rollback and final status.
- Keep Android 10/API 29 compatibility and gate newer APIs.
- Before every final commit run `python3 tools/ts18_theme.py validate` and `python3 -m unittest discover -s tests -v`; run Bash/sh syntax checks plus relevant Gradle lint/unit/build tasks. For standalone changes also run `:launcher:lintDebug`, `:launcher:testDebugUnitTest` and `:launcher:assembleDebug`; apply runtime-envelope checks to the signed/minified release APK because debug packaging is not release-qualification evidence.
